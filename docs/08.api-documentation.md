# API Documentation — Expendora

**Document Version:** 1.0
**Project:** Expendora — Personal Expense Management Application
**Last Updated:** July 2026
**Base URL:** `https://expendora-api.onrender.com/api`
**Status:** Reference Document (Pre-Implementation)

---

## Conventions

| Convention | Detail |
|---|---|
| **Base URL** | All endpoints are prefixed with `/api` |
| **Format** | All request and response bodies are `application/json` unless stated otherwise |
| **Authentication** | Protected routes require `Authorization: Bearer <access_token>` header |
| **Timestamps** | All dates/times are ISO 8601 format: `YYYY-MM-DDTHH:MM:SSZ` |
| **Error shape** | All errors return `{ "success": false, "message": "...", "code": "..." }` |

---

## Authentication

> All endpoints marked PROTECTED require a valid JWT access token in the Authorization header.
> Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...

---

## HTTP Status Codes

| Code | Meaning |
|---|---|
| `200` | OK — Request succeeded |
| `201` | Created — Resource created successfully |
| `400` | Bad Request — Invalid input or missing fields |
| `401` | Unauthorized — Missing or invalid token |
| `403` | Forbidden — Authenticated but not permitted |
| `404` | Not Found — Resource does not exist |
| `409` | Conflict — Duplicate resource (e.g., email already registered) |
| `422` | Unprocessable Entity — Validation error |
| `500` | Internal Server Error — Unexpected server failure |

# Auth Endpoints

## POST `/auth/register`

**Purpose:** Create a new Expendora user account. On success, issues an access token and a refresh token, and triggers a welcome email via n8n.

**Auth:** Public

**Request Body:**
```json
{
  "name": "Samith Narayanan",
  "email": "samith@example.com",
  "password": "SecurePass123"
}
```

| Field | Type | Required | Validation |
|---|---|---|---|
| `name` | string | Yes | Min 2 characters |
| `email` | string | Yes | Must be a valid email format |
| `password` | string | Yes | Min 8 characters |

**Success Response — `201 Created`:**
```json
{
  "success": true,
  "message": "Account created successfully.",
  "data": {
    "user": {
      "id": "64b1f2c3d4e5f6a7b8c9d0e1",
      "name": "Samith Narayanan",
      "email": "samith@example.com",
      "created_at": "2026-07-08T06:00:00Z"
    },
    "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "refresh_token": "dGhpcyBpcyBhIHJlZnJlc2ggdG9rZW4..."
  }
}
```

**Error Responses:**

| Status | Code | Message |
|---|---|---|
| `400` | `MISSING_FIELDS` | Name, email, and password are required. |
| `400` | `INVALID_EMAIL` | Email address format is invalid. |
| `400` | `WEAK_PASSWORD` | Password must be at least 8 characters. |
| `409` | `EMAIL_IN_USE` | An account with this email already exists. |
| `500` | `SERVER_ERROR` | An unexpected error occurred. |

**Example Error — `409 Conflict`:**
```json
{
  "success": false,
  "message": "An account with this email already exists.",
  "code": "EMAIL_IN_USE"
}
```

**Side Effects:**
- Triggers n8n webhook to send a welcome email to the registered address.

## POST `/auth/forgot-password`

**Purpose:** Accepts a registered email address and sends a password reset link to that address via n8n.

**Auth:** Public

**Request Body:**
```json
{
  "email": "samith@example.com"
}
```

**Success Response — `200 OK`:**
```json
{
  "success": true,
  "message": "If this email is registered, a password reset link has been sent."
}
```

> Note: The response is intentionally vague to prevent email enumeration attacks. The same response is returned whether or not the email exists.

**Error Responses:**

| Status | Code | Message |
|---|---|---|
| `400` | `MISSING_FIELDS` | Email is required. |
| `400` | `INVALID_EMAIL` | Email address format is invalid. |

**Side Effects:**
- If the email is registered, triggers an n8n webhook to send a password reset email containing a time-limited reset link.

# Receipt Endpoints

---

## POST `/receipts/upload`

**Purpose:** Upload a receipt image to the backend. The image is sent to Cloudinary for storage and then processed by Tesseract OCR. Returns the extracted data pre-filled for user review before saving an expense.

**Auth:** Protected

**Content-Type:** `multipart/form-data`

**Request Body:**

| Field | Type | Required | Detail |
|---|---|---|---|
| `image` | file | Yes | JPEG or PNG image of the receipt |

**Example (multipart form):**
```
POST /api/receipts/upload
Content-Type: multipart/form-data
Authorization: Bearer <token>

--boundary
Content-Disposition: form-data; name="image"; filename="receipt.jpg"
Content-Type: image/jpeg
<binary image data>
--boundary--
```

**Success Response — `200 OK`:**
```json
{
  "success": true,
  "message": "Receipt processed successfully.",
  "data": {
    "receipt_url": "https://res.cloudinary.com/expendora/image/upload/v1234567890/receipts/abc123.jpg",
    "ocr": {
      "merchant": "Starbucks KLCC",
      "amount": 18.50,
      "date": "2026-07-07",
      "line_items": [
        { "description": "Caramel Latte",    "amount": 15.00 },
        { "description": "Chocolate Muffin", "amount":  3.50 }
      ],
      "suggested_category": "Food",
      "confidence": "high"
    }
  }
}
```

> Note: `confidence` can be "high", "medium", or "low". When "low" or "medium", the app displays a "Please verify" prompt. Any null field means OCR could not extract that value and the user must fill it in manually.

**Partial OCR Response (when extraction is incomplete):**
```json
{
  "success": true,
  "message": "Receipt processed. Some fields could not be extracted.",
  "data": {
    "receipt_url": "https://res.cloudinary.com/expendora/...",
    "ocr": {
      "merchant": null,
      "amount": 45.00,
      "date": null,
      "line_items": [],
      "suggested_category": null,
      "confidence": "low"
    }
  }
}
```

**Error Responses:**

| Status | Code | Message |
|---|---|---|
| `400` | `NO_IMAGE` | No image file was attached to the request. |
| `400` | `INVALID_FORMAT` | Only JPEG and PNG image formats are accepted. |
| `401` | `UNAUTHORIZED` | Access token is missing or invalid. |
| `500` | `OCR_FAILED` | OCR processing failed. Please enter details manually. |
| `500` | `UPLOAD_FAILED` | Image could not be uploaded to storage. |

## POST `/expenses`

**Purpose:** Create a new expense record. Called after the user reviews OCR-extracted data or when manually adding an expense without a receipt.

**Auth:** Protected

**Request Body:**
```json
{
  "merchant": "Starbucks KLCC",
  "amount": 18.50,
  "currency": "MYR",
  "category": "Food",
  "date": "2026-07-07",
  "payment_method": "eWallet",
  "notes": "Morning coffee",
  "receipt_url": "https://res.cloudinary.com/expendora/..."
}
```

| Field | Type | Required | Validation |
|---|---|---|---|
| `merchant` | string | Yes | Min 1 character |
| `amount` | number | Yes | Must be greater than 0 |
| `currency` | string | No | Defaults to user's preferred currency |
| `category` | string | Yes | One of: Food, Transport, Shopping, Bills, Entertainment, Other |
| `date` | string | Yes | Format YYYY-MM-DD |
| `payment_method` | string | No | e.g. Cash, Card, eWallet |
| `notes` | string | No | Free text, max 500 characters |
| `receipt_url` | string | No | Cloudinary URL from a prior /receipts/upload call |

**Success Response — `201 Created`:**
```json
{
  "success": true,
  "message": "Expense created successfully.",
  "data": {
    "id": "64c2a1b3d5e6f7a8b9c0d1e2",
    "merchant": "Starbucks KLCC",
    "amount": 18.50,
    "currency": "MYR",
    "category": "Food",
    "date": "2026-07-07",
    "payment_method": "eWallet",
    "notes": "Morning coffee",
    "receipt_url": "https://res.cloudinary.com/expendora/...",
    "created_at": "2026-07-07T08:30:00Z"
  }
}
```

**Side Effects:**
- If this expense causes a budget category to reach >= 80%, triggers an n8n budget alert webhook.
- If this expense causes a budget category to exceed 100%, triggers an n8n budget exceeded webhook.

**Error Responses:**

| Status | Code | Message |
|---|---|---|
| `400` | `MISSING_FIELDS` | Merchant, amount, category, and date are required. |
| `400` | `INVALID_AMOUNT` | Amount must be a positive number. |
| `400` | `INVALID_CATEGORY` | Category must be one of the accepted values. |
| `400` | `INVALID_DATE` | Date format is invalid. Use YYYY-MM-DD. |
| `401` | `UNAUTHORIZED` | Access token is missing or invalid. |

## GET `/reports/monthly/export`

**Purpose:** Export the monthly report data as a downloadable CSV or PDF file.

**Auth:** Protected

**Query Parameters:**

| Parameter | Type | Required | Description |
|---|---|---|---|
| `month` | string | Yes | Month to export — format YYYY-MM |
| `format` | string | Yes | Export format: csv or pdf |

**Example Request:**
```
GET /api/reports/monthly/export?month=2026-07&format=pdf
Authorization: Bearer <token>
```

**Success Response — `200 OK`:**
- **Content-Type:** `text/csv` (for CSV) or `application/pdf` (for PDF)
- **Content-Disposition:** `attachment; filename="expendora-report-2026-07.pdf"`
- Response body is the raw file binary (not JSON).

**Error Responses:**

| Status | Code | Message |
|---|---|---|
| `400` | `MISSING_PARAMS` | Month and format parameters are required. |
| `400` | `INVALID_FORMAT` | Format must be either csv or pdf. |
| `400` | `INVALID_MONTH` | Month format is invalid. Use YYYY-MM. |
| `401` | `UNAUTHORIZED` | Access token is missing or invalid. |
| `404` | `NO_DATA` | No expense data found for this month. |

## PUT `/budgets`

**Purpose:** Set or update the monthly budget for the overall limit and/or individual categories. Budget limits persist month-to-month until changed.

**Auth:** Protected

**Request Body:** (all fields optional — include only what you want to update)

# n8n Webhook Triggers (Internal)

The following are internal calls made by the Flask backend to n8n. They are not called by the mobile app directly.

| Event | Trigger Condition | Webhook Payload |
|---|---|---|
| `welcome_email` | User successfully registers | `{ user_id, name, email }` |
| `password_reset` | User requests password reset | `{ email, reset_token, expires_at }` |
| `budget_alert` | Category spending reaches >= 80% of budget | `{ user_id, email, category, spent, budget, percentage }` |
| `budget_exceeded` | Category spending exceeds 100% of budget | `{ user_id, email, category, spent, budget }` |
| `monthly_summary` | End of calendar month (cron trigger in n8n) | Triggered by n8n scheduler; n8n calls /api/reports/monthly internally |
