# Functional Requirements — Expendora

Expendora is a personal expense management mobile application built with React Native (Expo) and a Flask API backend. The following functional requirements define the core system behaviour.

---

## FR-01 User Registration

### Description
New users must be able to create a personal account within the application.

### Requirements
| ID | Requirement |
|---|---|
| FR-01.1 | The system shall provide a registration form with fields for full name, email address, and password. |
| FR-01.2 | The system shall validate that the email address is in a correct format before submission. |
| FR-01.3 | The system shall enforce a minimum password length of 8 characters. |
| FR-01.4 | The system shall prevent registration with an email address that is already in use and display an appropriate error message. |
| FR-01.5 | Upon successful registration, the system shall create a user account, issue an authentication token, and navigate the user to the Onboarding screen. |
| FR-01.6 | All registration data shall be transmitted to the backend over HTTPS. |

---

## FR-02 User Login

### Description
Registered users must be able to securely authenticate and access their account.

### Requirements
| ID | Requirement |
|---|---|
| FR-02.1 | The system shall provide a login form with fields for email address and password. |
| FR-02.2 | The system shall authenticate the user against stored credentials via the Flask backend. |
| FR-02.3 | Upon successful login, the system shall issue a JWT token and navigate the user to the Dashboard. |
| FR-02.4 | The system shall display a clear error message when incorrect credentials are entered. |
| FR-02.5 | The system shall support session persistence so that users remain logged in across app restarts until they explicitly log out. |
| FR-02.6 | The system shall provide a "Forgot Password" option that initiates a password reset flow via email. |

---

## FR-03 Upload Receipt

### Description
Users must be able to upload physical or digital receipts for expense recording.

### Requirements
| ID | Requirement |
|---|---|
| FR-03.1 | The system shall allow users to capture a receipt image using the device camera. |
| FR-03.2 | The system shall allow users to select an existing image from the device photo gallery. |
| FR-03.3 | The system shall accept image formats including JPEG and PNG. |
| FR-03.4 | The system shall display a preview of the selected or captured image before submission. |
| FR-03.5 | Upon confirmation, the system shall upload the image to the Flask backend for processing. |
| FR-03.6 | The system shall display a loading indicator while the upload and processing are in progress. |
| FR-03.7 | Uploaded receipt images shall be stored server-side and linked to the corresponding expense record. |

---

## FR-04 OCR Processing

### Description
The system must automatically extract key data from uploaded receipt images to reduce manual data entry.

### Requirements
| ID | Requirement |
|---|---|
| FR-04.1 | The backend shall process uploaded receipt images using Optical Character Recognition (OCR). |
| FR-04.2 | The system shall attempt to extract the following fields from the receipt: merchant name, total amount, date of transaction, and individual line items where possible. |
| FR-04.3 | Extracted data shall be pre-populated into the expense entry form for user review before saving. |
| FR-04.4 | The user shall be able to edit any OCR-extracted values before confirming the expense. |
| FR-04.5 | If OCR fails to extract a field, that field shall remain blank and the user shall be prompted to fill it in manually. |
| FR-04.6 | The system shall display a confidence indicator or a "Please verify" prompt when extracted data may be inaccurate. |

---

## FR-05 Expense Categorization

### Description
All expenses must be assigned to a category to enable meaningful tracking and reporting.

### Requirements
| ID | Requirement |
|---|---|
| FR-05.1 | The system shall support the following predefined expense categories: Food, Transport, Shopping, Bills, Entertainment, and Other. |
| FR-05.2 | Each category shall have a unique colour used consistently throughout the application. |
| FR-05.3 | Users shall be able to manually select or change the category for any expense. |
| FR-05.4 | The system shall attempt to automatically suggest a category based on OCR-extracted merchant names (e.g., "Starbucks" → Food). |
| FR-05.5 | Users shall be able to filter and view expenses by category across the Expense List and Reports screens. |

---

## FR-06 Dashboard

### Description
The dashboard is the primary home screen and must provide users with an at-a-glance view of their financial status.

### Requirements
| ID | Requirement |
|---|---|
| FR-06.1 | The dashboard shall display the user's total account balance. |
| FR-06.2 | The dashboard shall display total spending for the current month and the remaining budget. |
| FR-06.3 | The dashboard shall show a spending breakdown chart (e.g., donut chart) by category for the current month. |
| FR-06.4 | The dashboard shall list the most recent transactions, showing merchant, category, amount, date, and payment method. |
| FR-06.5 | The dashboard shall display an AI-generated insight card with a personalised spending tip (e.g., "You spent 28% more on food this week"). |
| FR-06.6 | The dashboard shall provide quick-action buttons for: Scan Receipt, Add Expense, Send, and Save. |
| FR-06.7 | The dashboard shall show a notification indicator when there are unread alerts or budget warnings. |

---

## FR-07 Monthly Reports

### Description
Users must be able to view detailed reports of their spending over monthly periods.

### Requirements
| ID | Requirement |
|---|---|
| FR-07.1 | The system shall generate a monthly spending report showing total expenditure for a selected month. |
| FR-07.2 | The report shall include a breakdown of spending by category, displayed as both a chart and a data table. |
| FR-07.3 | The system shall allow users to navigate between months to view historical reports. |
| FR-07.4 | The system shall display a comparison of the selected month's spending against the previous month |
| FR-07.5 | The system shall show a bar or line chart illustrating daily or weekly spending trends within the selected month. |
| FR-07.6 | The system shall allow users to export a monthly report as a CSV or PDF file. |

---

## FR-08 Email Notifications

### Description
The system must send automated email notifications to keep users informed of important account and spending events.

### Requirements
| ID | Requirement |
|---|---|
| FR-08.1 | The system shall send a welcome email upon successful user registration. |
| FR-08.2 | The system shall send a password reset email when a user requests it via the "Forgot Password" flow. |
| FR-08.3 | The system shall send a budget alert email when a spending category reaches 80% of its set budget. |
| FR-08.4 | The system shall send a budget exceeded email when spending in any category surpasses its set limit. |
| FR-08.5 | The system shall send a monthly summary email at the end of each calendar month containing the user's spending totals and category breakdown. |
| FR-08.6 | Users shall be able to opt in or out of each type of notification email from the Settings screen. |

---

## FR-09 Budget Tracking  //future enhancement

### Description
Users must be able to set and monitor spending budgets to manage their finances.

### Requirements
| ID | Requirement |
|---|---|
| FR-09.1 | Users shall be able to set an overall monthly spending budget. |
| FR-09.2 | Users shall be able to set individual budget limits for each expense category. |
| FR-09.3 | The system shall track spending in real time and update budget progress whenever a new expense is added. |
| FR-09.4 | The system shall display a progress bar for each category showing amount spent versus the budget limit. |
| FR-09.5 | The system shall visually highlight a category in amber when spending reaches ≥80% of its budget. |
| FR-09.6 | The system shall visually highlight a category in red when spending exceeds its budget. |
| FR-09.7 | The system shall display a summary showing overall budget remaining for the current month. |
| FR-09.8 | Budget limits shall persist month-to-month unless the user modifies them. |
