# Project Scope — Expendora

## Overview

This document defines the boundaries of the Expendora mobile application for its initial release (v1.0). It clearly outlines which features and capabilities are **in scope** and which are **out of scope**, to ensure the development team, stakeholders, and contributors share a common understanding of the project's goals and limitations.

Expendora is a personal expense management mobile application built with **React Native (Expo)** for the frontend and a **Flask API** for the backend. It is designed to help individual users track, categorise, and understand their daily spending through a clean, intuitive interface.

---

## In Scope

The following features and capabilities are included in the v1.0 release of Expendora.

---

### SC-01 Receipt Upload

Users can upload physical or digital receipts directly within the app.

| ID | In-Scope Item |
|---|---|
| SC-01.1 | Capture receipt images using the device camera. |
| SC-01.2 | Select existing images from the device photo gallery. |
| SC-01.3 | Accept JPEG and PNG image formats. |
| SC-01.4 | Preview images before uploading. |
| SC-01.5 | Store uploaded receipt images server-side, linked to expense records. |

---

### SC-02 OCR (Optical Character Recognition)

The system automatically extracts expense data from uploaded receipt images to reduce manual entry.

| ID | In-Scope Item |
|---|---|
| SC-02.1 | OCR processing of uploaded receipt images via the Flask backend. |
| SC-02.2 | Extraction of key fields: merchant name, total amount, transaction date, and line items where possible. |
| SC-02.3 | Pre-population of the expense entry form with OCR-extracted data. |
| SC-02.4 | Ability for users to review and correct any extracted values before saving. |
| SC-02.5 | Fallback prompts when OCR cannot confidently extract a field. |

---

### SC-03 Expense Management

Users can create, view, edit, and delete expense records, with category classification.

| ID | In-Scope Item |
|---|---|
| SC-03.1 | Manual expense entry with fields for amount, merchant, date, category, and payment method. |
| SC-03.2 | Predefined expense categories: Food, Transport, Shopping, Bills, Entertainment, and Other. |
| SC-03.3 | Automatic category suggestion based on OCR-extracted merchant names. |
| SC-03.4 | Ability to edit or delete any existing expense record. |
| SC-03.5 | Expense list view with filtering by category and date range. |
| SC-03.6 | Dashboard overview showing monthly totals and recent transactions. |

---

### SC-04 Reports

The system generates visual spending reports to help users understand their financial patterns.

| ID | In-Scope Item |
|---|---|
| SC-04.1 | Monthly spending report showing total expenditure for a selected month. |
| SC-04.2 | Category breakdown displayed as a chart (e.g., donut/bar chart) and a data table. |
| SC-04.3 | Month-over-month spending comparison. |
| SC-04.4 | Daily or weekly spending trend chart within a selected month. |
| SC-04.5 | Export of monthly reports as CSV or PDF. |
| SC-04.6 | Navigation between historical months for report viewing. |

---

### SC-05 Email Summaries & Notifications

The system sends automated email notifications for key account and spending events.

| ID | In-Scope Item |
|---|---|
| SC-05.1 | Welcome email upon successful user registration. |
| SC-05.2 | Password reset email via the "Forgot Password" flow. |
| SC-05.3 | Monthly summary email at the end of each calendar month. |

---

### SC-06 User Authentication

Secure account registration and login for individual users.

| ID | In-Scope Item |
|---|---|
| SC-06.1 | User registration with name, email, and password. |
| SC-06.2 | JWT-based login and session persistence across app restarts. |
| SC-06.3 | Password reset via email. |
| SC-06.4 | Secure data transmission over HTTPS. |

---

## Out of Scope

The following features and capabilities are **explicitly excluded** from the v1.0 release of Expendora. These items have been deferred to avoid scope creep, reduce development complexity, or because they require third-party integrations outside the current project boundary.

---

### OS-01 Bank Integration

| Item | Reason for Exclusion |
|---|---|
| Direct connection to user bank accounts (e.g., Open Banking APIs) | Requires financial licensing, complex OAuth flows, and third-party bank API partnerships. Not feasible for v1.0. |
| Automatic import of bank transactions | Dependent on bank integration. Excluded accordingly. |
| Real-time bank balance display from external accounts | Dependent on bank integration. Excluded accordingly. |

---

### OS-02 Credit Card Integration

| Item | Reason for Exclusion |
|---|---|
| Linking and syncing credit card accounts | Requires PCI-DSS compliance and third-party card network integrations (e.g., Mastercard, Visa APIs). Out of scope for v1.0. |
| Automatic credit card transaction import | Dependent on credit card integration. Excluded accordingly. |
| Credit card reward or cashback tracking | Requires card-specific API access. Excluded. |

---

### OS-03 Automatic Bus Fare / Transit Tracking

| Item | Reason for Exclusion |
|---|---|
| Automatic detection and logging of bus, train, or transit fares | Requires access to GPS data, NFC/contactless card readers, or transit operator APIs (e.g., MyKad, Touch 'n Go). Not in scope for v1.0. |
| Integration with transit cards or commuter pass systems | Dependent on transit operator partnerships. Excluded. |

---

### OS-04 AI Financial Advisor

| Item | Reason for Exclusion |
|---|---|
| Personalised AI-driven financial planning or advice | Requires a large language model integration, financial domain training, and potential regulatory considerations. Excluded from v1.0. |
| Goal-based savings recommendations | Dependent on AI advisor capabilities. Excluded. |
| Predictive spending forecasts beyond simple trend display | Requires advanced ML modelling. Excluded. |

> **Note:** The dashboard does include a basic AI-generated insight card (e.g., "You spent 28% more on food this week") powered by simple rule-based logic or a lightweight API call. This is distinct from a full AI financial advisor and is **in scope**.

---

### OS-05 Investment Tracking

| Item | Reason for Exclusion |
|---|---|
| Tracking of stocks, shares, ETFs, or mutual funds | Requires integration with investment brokerage APIs (e.g., Bursa Malaysia, Yahoo Finance). Out of scope. |
| Portfolio performance reporting | Dependent on investment data feeds. Excluded. |
| Cryptocurrency tracking | Requires integration with crypto exchange APIs. Excluded. |
| Dividend or interest income recording | Not aligned with core expense-management purpose of v1.0. Excluded. |
