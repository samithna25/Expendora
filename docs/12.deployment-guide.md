# Deployment Guide — Expendora

**Document Version:** 1.0
**Project:** Expendora — Personal Expense Management Application
**Last Updated:** July 2026
**Status:** Approved

---

## Overview

This guide explains exactly how to deploy the full Expendora stack from zero to a live, working application. Follow every section in order — services depend on each other and must be configured before deployment.

```
Deployment Order

  1. MongoDB Atlas        (database -- needed by backend)
         |
         v
  2. Cloudinary           (image storage -- needed by backend)
         |
         v
  3. n8n                  (workflow automation -- needed by backend)
         |
         v
  4. Flask Backend        (API -- deployed to Render or Railway)
         |
         v
  5. Expo Mobile App      (frontend -- published via EAS Build)
```

## Part 1 — MongoDB Atlas

### 1.1 Create a Free Cluster

1. Log in to [MongoDB Atlas](https://cloud.mongodb.com).
2. Click **"Build a Database"**.
3. Select **M0 Free Tier** (512 MB storage — sufficient for v1.0).
4. Choose a cloud provider and region closest to your backend server (e.g., AWS `ap-southeast-1` for Malaysia).
5. Name the cluster: `expendora-cluster`.
6. Click **"Create Cluster"** — this takes approximately 3 minutes.

---

### 1.2 Create a Database User

1. In the left sidebar go to **Security > Database Access**.
2. Click **"Add New Database User"**.
3. Authentication method: **Password**.
4. Set a username and a strong password. Save these — you will need them for the connection string.
5. Role: **"Read and Write to any database"**.
6. Click **"Add User"**.

---

### 1.3 Whitelist IP Address

1. In the left sidebar go to **Security > Network Access**.
2. Click **"Add IP Address"**.
3. Click **"Allow Access from Anywhere"** — sets the rule to `0.0.0.0/0`.

> For production, restrict to the static IP of your Render or Railway server if available. The `0.0.0.0/0` rule is acceptable for free-tier deployments where static IPs are unavailable.

4. Click **"Confirm"**.

---

### 1.4 Get the Connection String

1. Go to **Database > Connect** on your cluster.
2. Choose **"Connect your application"**.
3. Select **Python**, version **3.6 or later**.
4. Copy the connection string:

```
mongodb+srv://<username>:<password>@expendora-cluster.xxxxx.mongodb.net/?retryWrites=true&w=majority
```

5. Replace `<username>` and `<password>` with the credentials from Step 1.2.
6. Append the database name before the `?`:

```
mongodb+srv://expendora_user:yourpassword@expendora-cluster.xxxxx.mongodb.net/expendora?retryWrites=true&w=majority
```

**Save this full string as `MONGO_URI`** — it will be added to your backend environment variables.

---

### 1.5 Create Collections

In Atlas, go to **Browse Collections > Add My Own Data**.
Create a database named `expendora` with the following collections:

| Collection | Purpose |
|---|---|
| `users` | User accounts |
| `expenses` | Expense records |
| `budgets` | Per-user budget settings |
| `alerts` | Budget warning notifications |
| `reset_tokens` | Password reset tokens |

## Part 3 — n8n Workflow Automation

### Option A — n8n Cloud (Recommended for simplicity)

1. Go to [n8n.io](https://n8n.io) and sign up for a free Cloud account.
2. Create a new workspace named `expendora`.

### Option B — Self-Hosted n8n (Free, more control)

Run n8n locally or on a VPS using Docker:

```bash
docker run -it --rm \
  --name n8n \
  -p 5678:5678 \
  -v ~/.n8n:/home/node/.n8n \
  n8nio/n8n
```

Access n8n at `http://localhost:5678`.

---

### 3.1 Configure Email Credentials in n8n

1. In n8n go to **Credentials > New Credential > SMTP**.
2. Enter your SMTP details:

| Field | Example Value |
|---|---|
| Host | `smtp.gmail.com` |
| Port | `587` |
| User | `your-email@gmail.com` |
| Password | Gmail App Password (not your login password) |
| SSL/TLS | `STARTTLS` |

3. Save as `Expendora SMTP`.

> To create a Gmail App Password: Google Account > Security > 2-Step Verification > App Passwords > Generate.

---

### 3.2 Create the Four Webhook Workflows

For each workflow below, create a new n8n workflow with a **Webhook** trigger node set to `POST`, then connect it to an **Email** node:

| Workflow Name | Webhook Path | Triggered By |
|---|---|---|
| Welcome Email | `/webhook/welcome-email` | User registration (WF-01) |
| Password Reset | `/webhook/password-reset` | Forgot password (WF-04) |
| Budget Alert | `/webhook/budget-alert` | Category reaches 80% (WF-10) |
| Budget Exceeded | `/webhook/budget-exceeded` | Category exceeds 100% (WF-10) |

Steps for each:
1. Add a **Webhook** node. Set method to `POST`. Copy the production webhook URL.
2. Add an **Email (SMTP)** node. Map payload fields to `To`, `Subject`, and `Body`.
3. Toggle the workflow to **Active**.

**Save all four webhook URLs** — they go into your backend environment variables.

---

### 3.3 Create the Monthly Summary Cron Workflow

1. Create a new n8n workflow.
2. Add a **Schedule Trigger** node. Set cron expression: `0 0 1 * *` (midnight, 1st of every month).
3. Add an **HTTP Request** node:
   ```
   GET https://your-backend-url.onrender.com/api/internal/users/active
   Header: X-Internal-Key: <INTERNAL_API_KEY>
   ```
4. Add a **Split In Batches** node to loop over the user list.
5. Inside the loop, add another **HTTP Request** node for each user's monthly report:
   ```
   GET /api/reports/monthly?month={{previous_month}}
   Header: X-Internal-Key: <INTERNAL_API_KEY>
   ```
6. Add an **Email (SMTP)** node to send the formatted monthly summary.
7. Toggle the workflow to **Active**.

## Part 4 — Flask Backend Deployment

### 4.1 Prepare the Repository

Ensure the `backend/` directory contains these files:

**`requirements.txt`**
```
flask==3.0.0
flask-jwt-extended==4.6.0
flask-cors==4.0.0
pymongo==4.6.0
bcrypt==4.1.2
pytesseract==0.3.10
Pillow==10.2.0
cloudinary==1.38.0
python-dotenv==1.0.0
requests==2.31.0
reportlab==4.1.0
weasyprint==61.0
gunicorn==21.2.0
```

**`Procfile`**
```
web: gunicorn run:app
```

**`runtime.txt`**
```
python-3.11.8
```

**`run.py`**
```python
from app import create_app

app = create_app()

if __name__ == "__main__":
    app.run()
```

---

### 4.2 Handle Tesseract as a System Dependency

Tesseract is a system binary, not a pip package. It must be installed during the deployment build step.

**For Render** — create `backend/render.yaml`:
```yaml
services:
  - type: web
    name: expendora-api
    runtime: python
    region: singapore
    buildCommand: |
      apt-get update && apt-get install -y tesseract-ocr tesseract-ocr-eng tesseract-ocr-msa
      pip install -r requirements.txt
    startCommand: gunicorn run:app
```

**For Railway** — create `backend/Dockerfile`:
```dockerfile
FROM python:3.11-slim

RUN apt-get update && apt-get install -y \
    tesseract-ocr \
    tesseract-ocr-eng \
    tesseract-ocr-msa \
    && rm -rf /var/lib/apt/lists/*

WORKDIR /app
COPY requirements.txt .
RUN pip install -r requirements.txt
COPY . .

CMD ["gunicorn", "run:app"]
```

---

### 4.3 Push to GitHub

```bash
git add backend/
git commit -m "chore: prepare backend for deployment"
git push origin main
```

---

### 4.4 Deploy to Render

1. Log in to [render.com](https://render.com).
2. Click **"New" > "Web Service"**.
3. Connect GitHub and select the `Expendora` repository.
4. Fill in the service settings:

| Setting | Value |
|---|---|
| Name | `expendora-api` |
| Region | Singapore |
| Branch | `main` |
| Root Directory | `backend` |
| Runtime | Python 3 |
| Build Command | *(use render.yaml — leave blank)* |
| Start Command | `gunicorn run:app` |
| Instance Type | Free |

5. Add all environment variables (see Part 5).
6. Click **"Create Web Service"**.

Your live API URL will be: `https://expendora-api.onrender.com`

> Free Render services sleep after 15 minutes of inactivity and take ~30 seconds to cold-start. This is acceptable for v1.0 development and testing.

---

### 4.5 Deploy to Railway (Alternative)

1. Log in to [railway.app](https://railway.app).
2. Click **"New Project" > "Deploy from GitHub repo"**.
3. Select the `Expendora` repository.
4. Set **Root Directory** to `backend`.
5. Railway auto-detects the Dockerfile if present.
6. Add all environment variables in the **Variables** tab.
7. Click **"Deploy"**.

Your live API URL will be: `https://expendora-api.up.railway.app`

## Part 5 — Environment Variables

This is the most critical configuration step. **Never commit these values to Git.**

---

### 5.1 Full Environment Variable Reference

#### Flask Core

| Variable | Description | Example Value |
|---|---|---|
| `FLASK_ENV` | Flask runtime environment | `production` |
| `SECRET_KEY` | Flask session secret key | `a3f8c21d9b4e76f0...` |

#### JWT Authentication

| Variable | Description | Example Value |
|---|---|---|
| `JWT_SECRET_KEY` | Secret key for signing and verifying JWT tokens | `d1e2f3a4b5c6d7e8...` |
| `JWT_ACCESS_TOKEN_EXPIRES` | Access token expiry in seconds | `900` (15 minutes) |
| `JWT_REFRESH_TOKEN_EXPIRES` | Refresh token expiry in seconds | `604800` (7 days) |

#### MongoDB

| Variable | Description | Example Value |
|---|---|---|
| `MONGO_URI` | Full MongoDB Atlas connection string | `mongodb+srv://user:pass@cluster.mongodb.net/expendora?...` |
| `MONGO_DB_NAME` | MongoDB database name | `expendora` |

#### Cloudinary

| Variable | Description | Example Value |
|---|---|---|
| `CLOUDINARY_CLOUD_NAME` | Cloudinary cloud name | `your-cloud-name` |
| `CLOUDINARY_API_KEY` | Cloudinary API key | `123456789012345` |
| `CLOUDINARY_API_SECRET` | Cloudinary API secret | `your-api-secret` |

#### n8n Webhooks

| Variable | Description | Example Value |
|---|---|---|
| `N8N_WEBHOOK_WELCOME` | Webhook URL — welcome email | `https://n8n.host/webhook/welcome-email` |
| `N8N_WEBHOOK_PASSWORD_RESET` | Webhook URL — password reset email | `https://n8n.host/webhook/password-reset` |
| `N8N_WEBHOOK_BUDGET_ALERT` | Webhook URL — budget 80% warning | `https://n8n.host/webhook/budget-alert` |
| `N8N_WEBHOOK_BUDGET_EXCEEDED` | Webhook URL — budget exceeded | `https://n8n.host/webhook/budget-exceeded` |

#### Internal and Upload Settings

| Variable | Description | Example Value |
|---|---|---|
| `INTERNAL_API_KEY` | Shared secret for internal endpoints (used by n8n cron) | `f1a2b3c4d5e6f7a8...` |
| `FRONTEND_URL` | Mobile app deep-link base URL for reset emails | `expendora://` |
| `MAX_CONTENT_LENGTH` | Maximum upload file size in bytes | `10485760` (10 MB) |
| `UPLOAD_FOLDER` | Temporary directory for image uploads | `/tmp/expendora_uploads` |

---

### 5.2 How to Generate Secret Keys

Run this in a Python shell to generate cryptographically secure random strings:

```python
import secrets
print(secrets.token_hex(32))
```

Example output:
```
a3f8c21d9b4e76f0a1c5d8e2b3f4a9c7d0e1f2a4b5c6d7e8f9a0b1c2d3e4f5
```

Generate **three separate keys** — one for `SECRET_KEY`, one for `JWT_SECRET_KEY`, and one for `INTERNAL_API_KEY`. Never reuse the same value.

### 5.3 Set Variables on Render

1. In your Render web service, click the **"Environment"** tab.
2. Click **"Add Environment Variable"** for each variable listed above.
3. Paste values without surrounding quotes.
4. Click **"Save Changes"** — Render will automatically redeploy.

### 5.4 Set Variables on Railway

1. In your Railway project, click the service.
2. Go to the **"Variables"** tab.
3. Click **"New Variable"** and add each variable.
4. Railway automatically redeploys on save.

## Part 6 — Expo Mobile App (EAS Build)

### 6.1 Set the Backend API URL

In the mobile app source, update the API config file to point to the live backend:

**`frontend-mobile/src/config/api.js`**
```javascript
const API_BASE_URL = __DEV__
  ? 'http://192.168.x.x:5000/api'              // Local dev (your machine IP)
  : 'https://expendora-api.onrender.com/api';  // Production

export default API_BASE_URL;
```

Replace `https://expendora-api.onrender.com` with your actual deployed backend URL.

> During local development with Expo Go, use your machine's local IP address — not `localhost` — because the phone and laptop must communicate over the same Wi-Fi network.

---

### 6.2 Install EAS CLI

```bash
npm install -g eas-cli
eas login
```

---

### 6.3 Configure EAS Build

Inside `frontend-mobile/`:


This generates `eas.json`:

### 6.4 Build the App

**For internal testing (Android APK):**

## Part 7 — Post-Deployment Checklist

Work through every item below after deployment to verify the system is fully operational end-to-end.

### Backend Health
- [ ] Visit `https://your-api-url/api/categories` in a browser — should return `200 OK` with category JSON.
- [ ] Check Render/Railway logs for any startup errors or missing environment variables.
- [ ] Confirm "Connected to MongoDB" message appears in startup logs.
- [ ] Confirm Tesseract binary is installed — look for tesseract in the build log output.

### Authentication
- [ ] `POST /api/auth/register` — creates user, returns access and refresh tokens.
- [ ] `POST /api/auth/login` — returns tokens for the registered user.
- [ ] `POST /api/auth/refresh` — returns a new access token using the refresh token.
- [ ] `POST /api/auth/forgot-password` — returns 200 and triggers reset email.

### Cloudinary
- [ ] Upload a receipt via `POST /api/receipts/upload`.
- [ ] Confirm `receipt_url` in the response is accessible in a browser.
- [ ] Confirm the image appears in the `expendora/receipts` folder in the Cloudinary dashboard.

### OCR
- [ ] Upload a clear receipt photo — confirm fields are extracted with `confidence: "high"`.
- [ ] Upload a blurry image — confirm `null` fields and `confidence: "low"` are returned.

### Expenses and Dashboard
- [ ] `POST /api/expenses` — creates expense with receipt URL attached.
- [ ] `GET /api/expenses` — returns the created expense in the list.
- [ ] `GET /api/dashboard` — returns populated summary, categories, and recent transactions.

### Email Notifications (n8n)
- [ ] Register new user — welcome email received within 60 seconds.
- [ ] Use forgot-password — reset email received and deep-link is correct.
- [ ] Add expense triggering 80% budget — budget alert email received.

### Reports and Export
- [ ] `GET /api/reports/monthly?month=YYYY-MM` — returns full report JSON.
- [ ] `GET /api/reports/monthly/export?month=YYYY-MM&format=csv` — CSV file downloads correctly.
- [ ] `GET /api/reports/monthly/export?month=YYYY-MM&format=pdf` — PDF file downloads and is readable.

## Part 8 — Troubleshooting

| Problem | Likely Cause | Fix |
|---|---|---|
| All routes return `500` | Missing or incorrect environment variable | Check Render/Railway logs; verify all env vars are set |
| `MongoServerError: bad auth` | Wrong `MONGO_URI` credentials | Re-check Atlas DB user credentials; regenerate if needed |
| `tesseract not found` | Binary not installed during build | Add `apt-get install tesseract-ocr` to build command or Dockerfile |
| Cloudinary upload returns `401` | Wrong API key or secret | Re-copy values from Cloudinary dashboard; check for trailing whitespace |
| n8n webhook not triggered | Wrong webhook URL or workflow not active | Re-copy URL from n8n; confirm workflow toggle is set to Active |
| JWT `401` on protected routes | Access token expired or wrong `JWT_SECRET_KEY` | Implement token refresh in app; confirm `JWT_SECRET_KEY` matches between deploys |
| OCR returns all `null` fields | Image too low quality or Malay lang pack missing | Add `tesseract-ocr-msa` to build; test with a clear, well-lit receipt photo |
| Render cold-start delays (~30s) | Free tier sleeps after 15 min of inactivity | Add an uptime monitoring ping or upgrade to a paid Render instance |
| CORS error from mobile app | `flask-cors` not configured | Add `CORS(app, origins="*")` in the Flask app factory for development |
| `.env` values not loading locally | Missing `python-dotenv` or wrong load path | Ensure `load_dotenv()` is called at the top of `run.py` |
